# Standing budget

Extends [Before a job](SKILL.md#before-a-job). The amount in [`scripts/budget`](scripts/budget) applies per UTC calendar day to the whole Boat account, including all pots and the Mac. Count VM time at list price even when the plan covers it. Start eligible heavy jobs, full end-to-end suites first, without asking. Keep Boat's live billing, size, start and concurrency limits in force.

`scripts/job` runs `scripts/budget SIZE TTL` immediately before handing the same size and TTL to Workspace under the same account credentials. The check reads Boat's published prices, rounds the size's full TTL cost up to six decimal places, and adds the maximum start fee from `boat --no-update limits --all --json`. For a read-only estimate, run `scripts/budget SIZE TTL` with the account access from [Before a job](SKILL.md#before-a-job). An estimate does not replace the check at launch.

| Decision | Action |
| --- | --- |
| `fits` | The wrapper delegates one start without a dialog, subject to the account-wide conditions below. |
| `over-budget` | Ask Walid to authorize this one run by name, purpose, size, TTL, `maximumChargeDollars`, and `remainderDollars`. With that approval, repeat the same launch with `--approved-max-dollars AMOUNT`. The wrapper reruns the check and honors the exception only if the new maximum stays within the approved amount. |
| `busy` | Wait for the other VM to stop and its usage to appear, then check again. |
| `contended` | Shorten the job within a measured TTL or coordinate an exclusive start with the other launchers. Use `--serialized` only while all launchers are actually excluded until this job's usage is visible. |
| `provider-blocked` or command error | Report the refusal or missing evidence. Resolve it and reread limits before starting. |

`last24hUsageSeconds` includes today's metered compute and part of yesterday. Per-VM usage is size-weighted, while the rolling aggregate's size weighting is unconfirmed. The check takes the higher of the raw seconds priced at the highest hourly rate and the credit seconds divided by `creditSecondsPerDollar`. The aggregate covers compute. The check separately bounds recent extra-start fees by multiplying `starts.day.used` by the highest current `overagePrices.startBrackets` fee. It includes one more maximum fee for the requested start, since `nextStartDollars` can change before creation. This assumes the rolling start count includes all billed starts and the current bracket ceiling bounds their fees. Do not use the estimate if you know the fee schedule changed or the count is incomplete. [Boat pricing and units](https://docs.boat.dev/pricing.md) · [Start windows and fees](https://docs.boat.dev/limits.md#extra-starts)

A `fits` result is conditional. Both account-wide `activeSandboxes` and `liveUsageSeconds` must be present and zero. By default each job must fit in half the estimated remainder, leaving room for a second job checked against the same idle account. This works only while at most two starts are pending visibility, all callers honor that allowance, and completed usage appears before another idle check. Count the entire delay through Workspace preparation and VM creation. Use `--serialized` only with an external reservation that excludes every other launcher until this run's usage is visible.

There is no hard account cap in this workflow. Boat exposes no atomic reservation or UTC-day fee total, and a pot's VM list is scoped to its environment. An unrestricted third start, a bypassing launcher, metering lag, an incomplete fee count, changed pricing that invalidates prior rates, or separately billed features can invalidate the bound. Keep saved snapshots and the AI proxy out of budgeted jobs. When you cannot establish the conditions, defer until the account is reconciled or coordinate an exclusive launch. Missing evidence, an active account, provider refusal, and contention cannot be overridden with a spending approval.
